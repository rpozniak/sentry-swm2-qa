# Автотести SENTRY SWM-2

pytest + pyserial: UART-драйвер у `framework/device_driver.py`, спільні фікстури в `conftest.py`, параметризовані перевірки у п'яти тестових файлах.

## Покриття

| Файл | Кейси |
|---|---|
| test_lamp.py | TC-LM-01–TC-LM-08 |
| test_relay.py | TC-RL-01, TC-RL-04–TC-RL-09 |
| test_health.py | TC-HL-01–TC-HL-05 |
| test_account.py | TC-AU-01–TC-AU-06 |
| test_alerts.py | TC-AL-01 у stable; TC-AL-02–TC-AL-06 у beta |

Разом 32 кейси з незалежними параметризованими виконаннями. TC-LM-09, TC-LM-10, TC-RL-02 та TC-RL-03 виконуються вручну. Логічні pulse і schedule перевіряються за переходами та часовими мітками UART; якщо потрібні переходи не спостерігаються, варіант має Blocked. Вікно оцінки UART становить ±50 мс для pulse та ±100 мс для schedule; це параметр методу спостереження, не допуск із PRD.

## Налаштування та запуск

Активувати `.venv` із кореня репозиторію. Скопіювати `config.example.json` у `config.local.json`, указати логін і пароль тестового профілю. За потреби вказати порт; інакше драйвер шукає єдиний USB-пристрій із VID 1A86. Можна використати SENTRY_USER і SENTRY_PASSWORD із середовища замість облікових даних у файлі. Локальна конфігурація виключена з Git.

Перед прогоном Wi-Fi має бути збережений на пристрої, профіль — створений; Guard у beta знятий з охорони. Закрити ручний UART-термінал.

```bash
source .venv/bin/activate
python -m pytest --collect-only -q
python -m pytest -m smoke --fw=2.1.0 --run-id=stable-smoke-01
python -m pytest --fw=2.1.0 --run-id=stable-01 --junitxml=reports/stable-01.xml
```

Для другої версії змінити `--fw` та ID прогону. `--run-id` має бути новим: попередні докази не перезаписуються. `--port=/dev/cu.usbmodem...` задає порт явно. Маркери `lamp`, `relay`, `health`, `account`, `alerts` дозволяють запускати одну фічу, `slow` — тривалі сценарії.

Порт відкривається один раз на сесію. Перед кожним кейсом фікстура відновлює передумови; після виконання зупиняє задачі, вимикає виходи й повертає відомі налаштування. Парольні перевірки відновлюють початковий пароль. Автоматичного повторення невдалого тесту, стирання NVS або OTA в наборі немає.

## Результати

`logs/<run-id>/` містить окремі очищені TX/RX-логи з часовими мітками для кожного параметра. `reports/<run-id>/results.json` і `SUMMARY.md` містять фактичні результати та посилання на докази. JUnit створюється параметром `--junitxml`. Паролі приховуються перед записом логів. Недоступна для версії функція має N/A, неможливість виконати передумови — Blocked.

Для ручного термінала використовується `python -m serial.tools.miniterm <port> 115200 --eol LF`. Прошивка сама повертає введені символи; прапорець `--echo` не потрібен.
