Кейси: [TEST_CASES.md](TEST_CASES.md). Правила виконання: [TEST_PLAN.md](TEST_PLAN.md).

## Межі покриття вимог

| Область PRD | Покриття та прогалини |
|---|---|
| LM-1 | Логічні команди та W510 входять; стан лампи після reboot/logout окремо не перевіряється. |
| LM-2 | Названі кольори фізично, допустимий RGB і помилки E502/E503 входять. |
| LM-3, LM-4 | Межі яскравості та її фізичне застосування у чотирьох режимах входять. Форма/період анімацій і E505 окремо не перевіряються. |
| LM-5 | Завершення 5-секундного таймера в UART і скасування входять. Фізичне вимкнення, межі 1/3600, E506/E507 та відлік залишені на розширення. |
| LM-6, LM-7, LM-8 | Status використовується як спосіб спостереження. Сцени, NVS лампи, повний формат status та пріоритети LED окремими кейсами не покриті. |
| RL-1 | Логічний стан, зовнішній LED і контакти розділені. W601/E602 поки не покриті. |
| RL-2 | Приріст cycles і збереження після reboot входять. Відсутність приросту при повторному on/off та збереження auto не покриті. |
| RL-3 | Допустимі pulse, завершення імпульсу та E603 входять. E604 й точне інструментальне вимірювання контактного імпульсу не покриті. |
| RL-4 | Цикл 2/2 і E606 входять. Schedule off використовується для очищення; його W605 і максимальні цикли не є окремими перевірками. |
| RL-5–RL-7 | Auto, health та вимкнення виходів при logout не покриті. |
| HL-1, HL-3 | Структура звіту, межі інтервалу, off та NVS інтервалу входять. Частота звітів у всіх станах, W901, health now при off і NVS самого off не покриті. |
| HL-2 | Генерування всіх попереджень не покрите. |
| AU-1 | Реєстрація профілю є підготовкою; її валідація та повторна реєстрація не покриті. |
| AU-2, AU-4 | Правильний вхід і user у whoami; lockout для однакових/різних login входять. E206 та debug-доступ у whoami не покриті. |
| AU-3, AC-1 | Завершення сесії підтверджується E003. Зупинка лампи/реле/вимірів та інші рівні доступу не покриті. |
| AU-5, AU-6 | Межі нового пароля, E205/E215 і збереження після reboot входять. Відмова зі старим паролем, passwd через OTA і sudo не покриті. |
| Розділ 1, AL-1, AL-2, AL-4 | E099 у stable; рівні/ID/позначка *, clear/E855 у beta входять. Усі джерела, 20-записний буфер та E854 не покриті. |
| AL-3, AL-5 | Ack заданого ID та W852 входять. Ack без ID, ack all як окрема функція, E851/W853, реакції реле/стану на CRITICAL не покриті. |
| WF-1–WF-5, OTA-1–OTA-12 | Мережа, version і перехід до beta забезпечують середовище. Повне тестування Wi-Fi/OTA не заявляється. |
| AC-2, ST-1–ST-4, GD-1–GD-5 | Парсер, всі стани й Guard поза обсягом; NORMAL і disarmed — передумови. |
| DS-1–DS-7, кнопки, система | Датчик і кнопки входять у фізичний стенд. Детальні функціональні перевірки цих областей не входять у 36 кейсів. |

ID вимоги в матриці означає заплановану перевірку описаної частини поведінки; він не є твердженням про повне покриття або успішний запуск.
