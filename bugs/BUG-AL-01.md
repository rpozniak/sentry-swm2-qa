# BUG-AL-01 — alert ack за ID повертає E851 для наявного сповіщення

**Severity:** Major. **Priority:** High.

**Середовище:** ESP32-S3 N16R8, UART 115200 8N1, macOS; тестовий профіль із доступом user.

| Версія | Результат |
|---|---|
| 2.1.0 | N/A: функція недоступна |
| 2.3.0 | Відтворюється для наявного ID. |

**Передумови:** 2.3.0, Wi-Fi та сесія активні, NORMAL, Guard disarmed, health off. Створено два INFO з джерелом test, записані їхні фактичні ID A і B; обидва видимі в alert list.

**Кроки:**

1. Виконати `alert list` і переконатися, що A та B присутні й мають позначку `*`.
2. Виконати `alert ack <A>`, де A — старіший фактичний ID зі списку.
3. Повторити `alert list` та перевірити позначки A і B.
4. Додатковий варіант: підтвердити запис через `alert ack all`, переконатися у відсутності `*`, потім виконати `alert ack <id>` для цього запису.

**Очікуваний результат:** За AL-3 команда з наявним ID підтверджує саме цей запис. Для вже підтвердженого ID має повертатися W852; E851 стосується відсутнього ID. [PRD, AL-2, AL-3](../reference/PRD.md).

**Фактичний результат:** У 2.3.0 наявний ID відхиляється з E851 no alert. У beta-01 записи #4 та #5 присутні, але alert ack 4 повертає E851; обидва залишаються непідтвердженими. У повторах так само відхиляється наявний #1. Для підтвердженого через ack all запису #3 команда також повертає E851 замість W852.

```text
[CIC #1 INFO] test: test alert
[CIC #2 INFO] test: test alert
TX alert ack 1
E851 no alert #1
[CIC] 2 alerts, 2 unacknowledged:
```

**Відтворюваність:** Наявний непідтверджений ID: 3/3. Уже підтверджений через ack all ID: 2/2 контрольних виконань.
