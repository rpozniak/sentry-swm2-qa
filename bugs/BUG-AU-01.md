# BUG-AU-01 — Зміна пароля не зберігається після reboot

**Severity:** Major. **Priority:** High.

**Середовище:** ESP32-S3 N16R8, UART 115200 8N1, macOS; тестовий профіль із доступом user.

| Версія | Результат |
|---|---|
| 2.1.0 | Відтворюється |
| 2.3.0 | Не відтворено; контрольні варіанти пройшли. |

**Передумови:** Wi-Fi та відомий профіль активні; початковий пароль P0 відомий. Підготовлено інший ASCII-пароль P6 або P32 відповідної довжини.

**Кроки:**

1. Виконати `passwd <P0> <new>` і дочекатися `[AUTH] password changed`.
2. Виконати `reboot`, потім `reconnect`.
3. Спробувати `login <user> <new>` і перевірити `whoami`.
4. Для відновлення доступу перевірити початковий P0. Значення паролів у логах замасковані.

**Очікуваний результат:** За AU-5 новий пароль зберігається в NVS та працює після reboot. [PRD, AU-5](../reference/PRD.md).

**Фактичний результат:** У 2.1.0 зміна підтверджується, але після reboot вхід із новим паролем відхиляється з E209; whoami показує відсутність сесії. Початковий P0 знову дозволяє вхід. Це спостерігається для довжини 6 та 32.

```text
[AUTH] password changed
TX reboot
...
E209 wrong login or password. Attempts: 1/3
not logged in
```

**Відтворюваність:** 2.1.0: 3/3 для P6 та 3/3 для P32. Початковий доступ після кожного виконання відновлений. Контроль 2.3.0: 0 Fail, 2 Pass для наведених варіантів.
